# Deployment Environment Variables

## Strictly Required Keys

- `DATABASE_URL`: PostgreSQL connection string used by Drizzle ORM to connect to the database (use the transaction connection pooler URL for serverless/Vercel).
  **Create:** provision a Postgres instance (Neon, Supabase, RDS, Vercel Postgres, etc.) — the provider's dashboard gives you the connection string directly.
- `BETTER_AUTH_SECRET`: 32-byte secret key used to sign and verify Better Auth session tokens and cookies.
  **Create:** `openssl rand -base64 32` — or `npx @better-auth/cli secret`.
- `BETTER_AUTH_URL`: Canonical public URL of your deployed application (e.g. `https://yourdomain.com`).
  **Create:** not generated — just your deployed domain, known once you've picked/pointed it.
- `NEXT_PUBLIC_APP_URL`: Base URL exposed to the frontend auth client for making authentication API requests.
  **Create:** same value as `BETTER_AUTH_URL`.
- `BROKER_CREDENTIALS_ENCRYPTION_KEY`: 32-byte symmetric encryption key used for AES-256-GCM encryption of broker credentials (Dhan & Motilal Oswal API tokens) stored at rest in the database.
  **Create:** `openssl rand -base64 32`. Generate once, keep stable — rotating it orphans every already-encrypted credential row in `broker_accounts`.

## Cron & Background Sync

- `CRON_SECRET`: Bearer authentication token used to secure scheduled cron endpoints under `/api/cron/*` (account balance sync, order polling, and rule evaluations).
  **Create:** any random string, e.g. `openssl rand -hex 32`. Set the same value on your cron scheduler's `Authorization: Bearer <token>` header (Vercel Cron sets this automatically from the env var).

## Broker Integrations

> **Dhan & Motilal Oswal**: no platform-level env keys needed — each user enters their own Client ID/API key/token in-app (**Settings → Integrations**), encrypted at rest with `BROKER_CREDENTIALS_ENCRYPTION_KEY`.
> - Dhan: user generates a 24h access token from web.dhan.co → Access DhanHQ APIs.
> - Motilal Oswal: user generates an API key at invest.motilaloswal.com/moapi, then pastes client code + API key + auth token (see adapter notes in [lib/runners/motilal/index.ts](lib/runners/motilal/index.ts)).

- `BROKER_RUNNER_STATIC_IP`: *(Optional)* Dedicated outbound static IP shown to users for brokers requiring IP whitelisting (Motilal Oswal, Zerodha F&O). Also sent as Motilal's mandatory `ClientPublicIp` audit header — without it MO falls back to `127.0.0.1`, which some accounts reject.
- `MOTILAL_VENDOR_API_KEY`, `MOTILAL_VENDOR_TAG`: *(Optional)* Platform-wide Motilal vendor key and registered vendor short name (request both from tradingapi@motilaloswal.com). When set, users connect Motilal by logging in on MO's own portal — they never paste an API key, the same way Zerodha works. Without them each user supplies their own self-built key.
- `BROKER_RUNNER_LOCAL_IP`, `BROKER_RUNNER_MAC_ADDRESS`: *(Optional)* Motilal's other mandatory audit headers (`ClientLocalIp`, `MacAddress`). Default to the static IP and `00:00:00:00:00:00`.
  **Create:** not generated by the app — comes from your hosting/network setup (e.g. a fixed-IP outbound proxy/NAT gateway in front of your deployment, or a static-IP add-on from your host). Set this var to whatever IP that infra gives you.

- `ZERODHA_API_KEY` / `ZERODHA_API_SECRET`: Kite Connect app credentials — platform-level, needed for the OAuth-style "Connect with Zerodha" login flow.
  **Create:** register a Kite Connect app at developers.kite.trade (₹2000/month subscription required) — the dashboard issues both values on app creation.

- `METAAPI_TOKEN`: Auth token for the MetaApi.cloud bridge (MT5 tick feed + order execution).
  **Create:** sign up at metaapi.cloud → Dashboard → generate an API token (Provisioning/Trading token).
- `METAAPI_STREAM_ACCOUNT_ID`: The MT5 trading account registered with MetaApi, used for the shared streaming connection.
  **Create:** in the MetaApi dashboard, add/link your MT5 account — it's assigned an account ID once provisioned.

## AI Copilot (at least one model provider recommended)

- `GROQ_API_KEY`: API key for Groq models (ChatGPT OSS 120B, etc.).
  **Create:** console.groq.com → API Keys → Create.
- `GOOGLE_GENERATIVE_AI_API_KEY`: API key for Google Gemini models.
  **Create:** aistudio.google.com/apikey → Create API key.
- `OPENAI_API_KEY`: API key for OpenAI models.
  **Create:** platform.openai.com/api-keys → Create new secret key.
- `KEIRO_API_KEY`: API key for Keiro web search, research tools, and per-ticker news lookups.
  **Create:** from Keiro Labs directly — no self-serve portal confirmed in this codebase's research; get key + docs from Keiro.
- `KEIRO_API_BASE_URL`: Base host for Keiro API requests.
  **Create:** get the confirmed base URL from Keiro's own docs/MCP server README — do NOT guess (see caveat in [lib/ai/tools/web-search.ts](lib/ai/tools/web-search.ts)).
